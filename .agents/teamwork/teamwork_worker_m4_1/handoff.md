## 1. Observation

### Recurring Event Exceptions & Ghost Occurrences
- In `frontend/js/calendar/rrule.js`, `RRuleParser.expandAll(events, rangeStart, rangeEnd)` previously expanded master recurring events without checking the existence of child exceptions (`parent_event_id == master.id`).
- When an event exception had `is_cancelled === true` (tombstone generated by `DELETE /events/{id}?scope=this`), `expandAll` simply skipped the tombstone row, but the master series generator continued to produce a synthetic occurrence for that date, leaving a "ghost" occurrence on the calendar grid.
- When an event exception was modified (`is_exception === true && !is_cancelled`), `expandAll` pushed the modified exception row, while the master expansion simultaneously yielded the un-modified occurrence for the original timeslot, resulting in duplicate entries.
- In `backend/app/crud/event_crud.py:34-36`, `get_by_range` deliberately queries cancelled tombstones (`(Event.is_cancelled == True) & (Event.is_exception == True) & (Event.parent_event_id.isnot(None))`) so that client-side expansion can detect which occurrences were deleted.

### Bidirectional Task-Calendar Real-Time Synchronization
- In `frontend/js/pages/calendar.js`, events were only refreshed via the legacy `document.addEventListener('task-changed')`.
- Tasks toggled or updated in the Calendar view (e.g. `agenda-view.js` and `event-card.js`) lacked uniform local state store synchronization (`store.get('tasks')`).
- Other task mutations in `frontend/js/todo/` (`task-form.js`, `task-detail.js`, `suggestions.js`, `todo.js`) and AI assistant tool executions in `frontend/js/ai/chat-panel.js` did not dispatch the canonical `window.dispatchEvent(new CustomEvent('planify:data-changed', { detail: { source, action, type } }))` required for cross-module reactive synchronization.
- As a consequence, completing or updating an item in To-Do or AI Assistant required a manual page refresh (F5) to reflect on Calendar, and vice-versa.

### AI Agent Parameter Parsing & Exceptions
- In `backend/app/ai/tool_executor.py:118, 143, 219`, `date.fromisoformat(val)` was called directly on string parameters. In Python 3.11, calling `date.fromisoformat("2026-11-02T10:00:00")` raises `ValueError: Invalid isoformat string`.
- When the LLM produced ISO timestamps for task due dates or time strings, unhandled exceptions were raised.
- In `backend/app/ai/agent.py:75`, tool call arguments were parsed with raw `json.loads(tc["function"]["arguments"])` without defensive fallback against malformed inputs.

## 2. Logic Chain

1. **Recurrence Exception Deduplication & Tombstone Suppression**:
   - `RRuleParser` in `frontend/js/calendar/rrule.js` was augmented with `matchesOriginalStart(excOriginalStart, occStartDate)` and `isOccurrenceSuppressed(occDate, exceptions)`.
   - `matchesOriginalStart` handles timestamp matching within a 60-second tolerance, local wall-clock date-time comparison (`YYYY-MM-DD HH:mm`), UTC date-time comparison, and date-only comparison.
   - In `expand(event, rangeStart, rangeEnd, exceptions)`, each candidate occurrence generated across `DAILY`, `WEEKLY`, `MONTHLY`, and `YEARLY` rules is evaluated against `isOccurrenceSuppressed`. If an occurrence matches a child exception (whether cancelled or modified), it is omitted from the expansion.
   - In `expandAll(events, rangeStart, rangeEnd)`, child exceptions are indexed by `parent_event_id`. Cancelled tombstones (`is_cancelled === true`) are suppressed from the rendered list, and modified child exceptions (`is_exception === true && !is_cancelled`) are added exactly once at their updated start/end times.
   - This eliminates both duplicate timeslots and ghost tombstones.

2. **Bidirectional Reactive Sync via `planify:data-changed`**:
   - Added `toggleCalendarTaskComplete(taskId, currentStatus)` in `frontend/js/calendar/task-adapter.js`. It calls `PATCH /tasks/{id}/complete`, updates the task entry in `store.get('tasks')`, and dispatches `window.dispatchEvent(new CustomEvent('planify:data-changed', { detail: { source: 'calendar', action: 'toggle-task', type: 'task', id: taskId } }))`.
   - Connected `frontend/js/calendar/event-card.js` and `frontend/js/calendar/agenda-view.js` to use `toggleCalendarTaskComplete`.
   - In `frontend/js/calendar/day-view.js` and `week-view.js`, added `planify:data-changed` dispatch for drag & drop moves and bottom-edge duration resizes.
   - In `frontend/js/calendar/event-form.js`, added `planify:data-changed` dispatch for quick creation, full modal creation, updates, and deletions for both events and tasks.
   - In `frontend/js/todo/task-detail.js`, created `notifyChanged(action)` dispatching `planify:data-changed` on title edits, subtask additions/completions/deletions, My Day toggles, due date changes, recurrence changes, list reassignments, time-blocking adjustments, and task deletions.
   - In `frontend/js/pages/calendar.js` and `frontend/js/pages/todo.js`, registered listeners for `planify:data-changed` on `window` to trigger reactive data reload (`this.updateView()` / `this.fetchTasks()`) without requiring page refresh (F5).

3. **AI Agent Error Hardening & Real-Time Trigger**:
   - In `backend/app/ai/tool_executor.py`, added robust parsers: `parse_date`, `parse_time`, and `parse_datetime` that seamlessly handle date strings, ISO datetime strings with timezone offsets, and truncated time formats.
   - In `backend/app/ai/agent.py`, wrapped tool call argument parsing in defensive try/except to prevent agent turn crashes.
   - In `frontend/js/ai/chat-panel.js:247`, ensured that whenever AI tools execute, `window.dispatchEvent(new CustomEvent('planify:data-changed', { detail: { source: 'ai-assistant', action: 'tool-executed', type: 'all', toolCalls } }))` is dispatched.
